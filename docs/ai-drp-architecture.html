AI-Enabled MSME DPR Platform

Application Architecture

Repository: AI_DRP  ·  Stack: React + Vite / Express + MongoDB  ·  Generated from codebase structure  ·  Bilingual EN / TE

Purpose. Guide entrepreneurs to create bank-ready Detailed Project Reports (DPRs), match them to central and Andhra Pradesh MSME schemes, and support AI-assisted drafting, analytics, and admin document workflows — with optional AP MSME ONE portal integration.

5. Scheme Finder (client-first matching)

Matching logic lives primarily on the client under client/src/lib/ventureMatch/. The server adds an LLM helper for clarifying free-text answers (ventureMatchHelp.service).
ModuleRole

AP domicile gate applies only to AP state schemes (EDP, FPP, Tech Upgrade, Parks, OBMMS, CMEP). Central schemes remain available to AP residents.

10. End-to-end flows

A. Scheme → Individual DPR

  1. User answers Scheme Finder questions; client evaluator narrows 16 schemes.
  2. Optional help bubble: chip tree first, then LLM via /api/ai.
  3. “Generate DPR for this Match” writes handoff + navigates to Individual DPR with scheme code.
  4. Step 1 shows scheme brief; form fields / uploads adapt via schemeFormConfig.
  5. Drafts save through cluster DPR APIs; generate produces bank-ready document (EN/TE).

B. Cluster DPR

  1. User fills cluster steps in ClusterDPRCreation + shared AI suggestion widgets.
  2. Server clusterDPR.service persists sections and generates narrative / tables.
  3. Preview via ClusterDPRDocumentView; export PDF (incl. HTML capture path).

C. AI Guided Builder

  1. Session started under /api/dpr/sessions.
  2. Per-step analyze (/builder/analyze) and chat (/builder/chat) grounded on prompts in constants/.
  3. Final DPR downloadable as PDF/DOCX from session endpoints.

11. Cross-cutting product capabilities

  • Bilingual: react-i18next locales + server translation service; DPR view language switch.
  • Offline / mock: offlineDetector, mockData, offline QA / DPR helpers for degraded networks.
  • RBAC: client rbac.ts + server role on User; admin routes gated.
  • Quality loop: feedback + ML/quality services → admin analytics.
  • Deploy: client/server vercel.json; Railway references in helmet CSP for hosted API.

12. Architecture principles (as implemented)

  • SPA + API: UI never talks to Mongo directly; all persistence through Express.
  • Domain packs on client: Scheme matching and scheme brochure copy ship with the SPA for snappy UX; LLM used when rules need language understanding.
  • Shared DPR document view: Individual flow reuses cluster document rendering via payload adapter.
  • Scheme-aware forms: One 18-step skeleton; scheme code toggles fields, hidden steps, and uploads.
  • AI as co-pilot: Suggestions and fill-all assist; human review before generate.
